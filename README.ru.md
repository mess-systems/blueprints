# Типовые архитектуры mess.systems

Типовые архитектуры (blueprints) **mess.systems**, по одной на каждую возможность компании.

Типовая архитектура это готовое решение для одной возможности. Она отвечает на четыре вопроса:

1. **Из чего собрано.** Компоненты из [технологического радара](https://github.com/mess-systems/tech-radar), у каждого ссылка на карточку и кольцо.
2. **Как называются части.** Имена, метки и теги по [стандарту именования](https://github.com/mess-systems/naming-standard).
3. **Как настроено.** Примеры конфигураций. Это заготовки, которые показывают форму настройки, а не копия работающей системы.
4. **Почему так.** Обоснование каждого выбора и отвергнутые варианты.

## Типовые архитектуры

| Папка | Возможность | Статус |
|---|---|---|
| [endpoint/](endpoint/) | Рабочее устройство сотрудника: ноутбуки и стационарные компьютеры, резидентные агенты, стандартные приложения | Черновик, развивается |
| [obs-mcp-readonly/](obs-mcp-readonly/) | Доступ агентов только на чтение к Kubernetes, метрикам и логам через MCP | Черновик, развивается |
| [net-mesh/](net-mesh/) | Частная сеть: координатор, группы и политики, подключение узлов, раздельный DNS, публикация продуктов | Черновик, развивается |

Следующие: AI-шлюз, идентичность, CI.

## Практики

Практика описывает, как ведётся работа над возможностями, а не саму возможность. Папка практики называется по практике.

| Папка | Практика | Статус |
|---|---|---|
| [agent-assisted-network-rollout/](agent-assisted-network-rollout/) | Внедрение изменений сети и доступа с ИИ-агентами: роли, этапы, контрольные точки, доказательства | Черновик, развивается |

## Как связаны три репозитория

| Репозиторий | Отвечает на вопрос |
|---|---|
| [naming-standard](https://github.com/mess-systems/naming-standard) | Как называть |
| [tech-radar](https://github.com/mess-systems/tech-radar) | Какие технологии и насколько твёрдо |
| blueprints (этот) | Как технологии складываются в работающую возможность |

Каждая карточка радара перечисляет типовые архитектуры, в которых участвует технология, поэтому ссылки работают в обе стороны.

## Устройство папки

```
<capability>/
  README.md        описание, состав, имена, обоснование, открытые вопросы
  examples/        заготовки конфигураций, явно помеченные как примеры
```

Имя папки это возможность, а не продукт (`endpoint`, а не название MDM), по правилу стандарта именования.

## Чего в типовой архитектуре нет никогда

Имён хостов, IP-адресов, реальных конфигураций, путей к секретам, групп доступа, инвентаря устройств и версий агентов. В примерах используются имена в домене `mess.systems`, например `gateway.ai.corp.svc.mess.systems`.

## Изменения

Изменение это pull request с кратким обоснованием. Новый компонент сначала получает карточку в радаре.
